WEB TECHNOLOGY • UNIT 3

Web Services & AJAX

Complete theory notes covering Web Services, SOAP, REST, AJAX and modern asynchronous web communication.

1. Introduction to Web Services

1.1 What is a Web Service?

A web service is a software system that allows different applications to communicate and exchange information over a network, usually the Internet. Web services make it possible for applications developed using different programming languages and running on different platforms to work together.

For example, one application may be developed in Java while another application is developed using Python or JavaScript. A web service can provide a common method through which these applications exchange data.

1.2 Basic Working of a Web Service

Client Application

↓ Request

Internet / Network

↓

Web Service

↓

Server / Database

↓ Response

Client Application

In this process, the client sends a request to the web service. The web service processes the request, communicates with the required system or database, and sends a response back to the client.

1.3 Characteristics of Web Services

  • They support communication between different applications.
  • They can exchange structured data over a network.
  • They are platform independent.
  • They can be used by websites, mobile applications and software.
  • They help different systems work together.

1.4 Advantages of Web Services

  • Allow communication between different technologies.
  • Promote software reusability.
  • Make data sharing easier.
  • Support distributed applications.
  • Can be used by multiple clients.

1.5 Disadvantages of Web Services

  • Network communication may introduce delays.
  • Security must be properly managed.
  • Complex services can be difficult to maintain.
  • Internet connectivity is often required.

1.6 Applications

  • Online payment systems
  • Weather information services
  • Maps and location services
  • Online shopping applications
  • Mobile applications
  • Social media platforms

1.7 Real-Life Example

Consider a travel website that displays flight information. Instead of storing all airline information itself, the website can communicate with airline web services. The service returns information such as available flights, timings and prices.

Important Exam Points

  • A web service allows applications to communicate over a network.
  • Web services support interoperability between different platforms.
  • They commonly follow a request and response model.

2. SOAP Web Services

2.1 Introduction to SOAP

SOAP stands for Simple Object Access Protocol. It is a protocol used for exchanging structured information between applications over a network.

SOAP messages are traditionally represented using XML. The protocol provides a structured way for a client and server to communicate.

2.2 Structure of a SOAP Message

SOAP Message

│

├── Envelope

│ ├── Header

│ └── Body

│

└── Response Message

2.3 SOAP Envelope

The SOAP envelope is the main container of a SOAP message. It identifies the XML document as a SOAP message and contains the other parts of the message.

2.4 SOAP Header

The header can contain additional information related to the message, such as information needed during message processing.

2.5 SOAP Body

The body contains the main information or request being sent between the client and the web service.

Advantages of SOAP

  • Provides a standardized communication structure.
  • Supports structured XML messages.
  • Useful for enterprise-level applications.
  • Can support formal communication requirements.

Disadvantages of SOAP

  • SOAP messages can be large because they use XML.
  • Processing can be more complex than simpler approaches.
  • It may require more bandwidth than lightweight formats.

Real-Life Example

Large organizations may use structured web service communication to connect different business applications, such as customer, banking or inventory systems.

3. RESTful Web Services

3.1 Introduction to REST

REST stands for Representational State Transfer. REST is an architectural style used for designing web services.

RESTful services commonly use HTTP methods to perform different operations on resources. A resource can represent information such as a student, product, user or order.

3.2 Common HTTP Methods

  • GET: Used to retrieve information.
  • POST: Used to create new information.
  • PUT: Used to update information.
  • DELETE: Used to remove information.

3.3 REST Working Diagram

Web or Mobile Application

↓ HTTP Request

REST API

↓

Server / Database

↓

JSON or Other Data Response

↓

User Application

3.4 Example of REST API Concept

GET /students

This type of request can be used to ask a web service for a collection of student information.

Advantages of REST

  • Simple and easy to understand.
  • Works well with web technologies.
  • Supports different data formats.
  • Commonly used in modern web and mobile applications.

Disadvantages of REST

  • Different APIs may follow different design patterns.
  • Security and authentication must be implemented properly.
  • Complex applications may require careful API design.

Real-Life Example

A shopping application can send a request to a product API to retrieve product names, prices and availability. The API sends the requested information back to the application.

4. AJAX – Asynchronous JavaScript and XML

4.1 Introduction

AJAX stands for Asynchronous JavaScript and XML. It is a technique used to exchange data with a server without requiring the complete web page to reload.

AJAX makes web applications faster and more interactive. A web page can request new information from a server and update only the required part of the page.

4.2 Why is AJAX Called Asynchronous?

In asynchronous communication, the browser can continue performing other tasks while a request is being processed. When the response is received, JavaScript can update the required part of the web page.

4.5 Technologies Used with AJAX

  • HTML – Provides page structure.
  • CSS – Controls presentation and design.
  • JavaScript – Handles interaction and requests.
  • XML or JSON – Can be used for data exchange.

4.6 Simple AJAX Concept

User clicks a button
        ↓
JavaScript sends a request
        ↓
Server processes the request
        ↓
Server sends data back
        ↓
JavaScript updates the web page

4.7 Advantages of AJAX

  • Improves the speed and responsiveness of web pages.
  • Reduces unnecessary complete page reloads.
  • Provides a better user experience.
  • Allows dynamic content updates.

4.8 Disadvantages of AJAX

  • Depends on JavaScript for many features.
  • Can make application development more complex.
  • Improper handling of requests can cause errors.
  • Security must be considered when exchanging data.

4.9 Applications of AJAX

  • Search suggestions
  • Live chat applications
  • Social media feeds
  • Online forms
  • Dynamic dashboards

4.10 Real-Life Example

When you type a search query on a website and suggestions appear while you are still typing, the application can use asynchronous communication to request relevant information without completely reloading the page.

Important Exam Points

  • AJAX stands for Asynchronous JavaScript and XML.
  • AJAX allows communication with a server in the background.
  • It can update parts of a web page without a full reload.
  • Modern AJAX applications commonly exchange data using JSON.

5. Data Exchange: XML and JSON

5.1 XML

XML stands for Extensible Markup Language. It is used to store and exchange structured data. XML uses custom tags to describe information. 

<student>
    <name>Aayush</name>
    <course>B.Tech</course>
</student>

5.2 JSON

JSON stands for JavaScript Object Notation. It is a lightweight format commonly used to exchange data between web applications and servers. 

{
    "name": "Aayush",
    "course": "B.Tech"
}

5.3 XML and JSON Comparison

XML

Structured using opening and closing tags

↓

JSON

Structured using objects and key-value pairs

Applications

XML and JSON are used to exchange information between applications. Modern web APIs commonly use JSON because it is lightweight and easy for JavaScript applications to process.

6. Client-Server Communication

6.1 Introduction

Most web applications follow a client-server model. The client is generally the user's browser or application, while the server provides data, services or application functionality.

6.2 Working Process

Client / Browser

↓ Sends Request

Web Server

↓ Processes Request

Application / Database

↓ Generates Result

Response Sent to Client

Web services and AJAX are important technologies used to improve communication between clients and servers.

Real-Life Example

When a student logs into an educational website, the browser sends login information to the server. The server verifies the information and sends an appropriate response to the browser.

Unit 3 Summary

Unit 3 introduces important technologies that allow web applications to communicate with servers and other software systems. Web services provide a method for applications to exchange information over a network.

SOAP provides a structured protocol for exchanging messages, while REST is a widely used architectural approach for modern web APIs. AJAX improves web application interactivity by allowing data to be exchanged asynchronously without requiring a complete page reload.
